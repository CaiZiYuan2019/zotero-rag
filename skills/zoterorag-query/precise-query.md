# 精确查询与子代理提示词

本流程用于[查询 Skill](../zoterorag-query.md)的精确查询。主代理与各子代理使用已初始化的检索库、已有的书目元数据副本、解析文本及解析图像。严格要求台账文件零写入时，使用本地快照；CLI 启动会初始化台账及模型配置。将搜索限定在本次指定范围，跳过既有报告。源 Zotero 库和原始 PDF 由用户本人手工阅读、核对或写作。

## 从检索到最终评估

1. **检索。** 主代理记录问题、所需证据、文献或集合范围（含是否纳入子集合）和检索深度，亲自发起首查并保存完整响应。按子问题、术语或集合分派后续检索。检索者交回逐次结果及按父条目归组的候选附件。零命中时在约定范围内换词，记录覆盖缺口。
2. **精读。** 主代理把候选文档和待回答的问题交给精读者。精读者打开对应的 `document.md` 或解析图像，阅读方法、结果、上下文和图注。逐项写出暂定结论、适用条件、相反证据与可复查的位置。
3. **独立复核重要结论。** 主代理给每项影响最终回答的重要结论编号，另派未参与该项检索和精读的专职复核者。交给复核者待核问题、范围和文档 ID。复核者自行检索或定位，重新阅读解析文本或查看解析图像，先独立记录观察，再与待核结论逐项比对，交回“支持／需修正／证据不足”、理由及证据位置。两个检索面命中同一段只算一处证据。缺少独立复核者时，标记对应结论“未独立复核”。
4. **主代理最终评估。** 对照精读记录与独立复核记录，检查双方引用的段落、图像、单位和条件，决定采纳、修正或暂缓哪项结论。分歧未解时保留双方依据，并说明这对回答的影响。由主代理完成报告和链接检查。

## 可直接分派的子代理提示词

每次分派只选一个角色。主代理填写花括号中的内容，并给执行者本页及独立的工作目录。深度可写为“集合内做题名、全文各一次，每次最多 20 条”或“逐篇核对方法段、结果段及指定图注”。

```text
角色为{检索者 / 精读者 / 专职独立复核者}。本次子问题为{问题或待核问题编号}。
文献范围为{集合 key、子集合、年份、纳入及排除条件或候选文档 ID}。
检索范围为{允许的检索面、起始词、可扩展的变体}。执行深度为{查询次数、limit/top-k、精读篇数、章节或图表、停止条件}。
使用{本次工作目录}和查询编号前缀{前缀}。证据来源限于台账、已有书目副本、解析文本及图像。跳过既有报告。

检索者保存每次完整响应及全部返回行，交回查询清单和同篇附件映射。
精读者阅读指定解析材料，交回逐项结论、上下文、短摘录或图像、文档与附件 ID 及证据位置。
独立复核者自行定位并重读材料，检查反例、数值、单位、版本和适用条件；对每项重要结论交回独立判断、理由及证据位置。
按下文归档查询与采用的证据。说明零命中、未覆盖部分及仍待核实的字段。最终评估由主代理负责。
```

## 从命中定位到解析材料

| 字段 | 用法 |
|---|---|
| `document_id` | 元数据和集合检索返回台账已解析的文档 ID，可直接用于 `documents show <document_id>`。它可与附件 key 不同。只有元数据时回退到附件 key，此时 `document_kind` 为 `metadata_only`。全文和向量命中同样使用返回的文档 ID。 |
| `attachment_key`、`parent_key` | 前者标识命中的 Zotero 附件，后者是 `parent_item_key` 的别名。按父条目归组，同篇多个附件分别保留。独立附件可无父条目。`source_id` 依次取父条目 key、附件 key 或文档 ID，用于按来源计数。 |
| `chunk_id` | 元数据或集合行沿用附件 key 作为该字段值；全文和向量行给出实际分块 ID，可据此在对应文档的 `chunks.jsonl` 定位。 |

对指定集合，先用 `search-by-collection` 确定附件范围并检查 `--limit` 是否截断。全文或向量接口没有该集合过滤参数时，将命中与已确认的附件范围取交集，记录过滤前后数量。若全库 top-k 或集合列表已截断，优先在范围内的 `document.md` 直接查找，并注明覆盖限制。

用台账 `attachments` 表按同一 `parent_key` 枚举兄弟附件，包括未命中的附件。逐份记录附件 key、可用的文件名、解析状态及采用理由。译本、副本、正文和补充材料按同一来源计数，证据精确到实际读过的解析文档。若命中只有元数据，检查范围内的兄弟附件有无解析材料。均无材料时，只报告书目信息与全文证据缺口。

用 `documents show <document_id> --consumer manual` 返回的 `document.artifact.document_md` 打开解析全文，从相邻段落确认对象和条件；用 `chunks.jsonl` 定位分块，用返回的 `file_ref` 及 `images/original_manifest.json` 定位解析图像。引用注明“解析文本”或“解析图像”，附文件名、节、行或图表号。图注缺损、数值模糊或印刷页码不明时，写明解析材料能够支持的内容，其余列为待用户手工核对。

## 书目核对与用户手工回查

代理按返回的 ID 对照台账和已有的 Zotero、Crossref 元数据副本，记录题名、作者、年份、刊名、卷期页及 DOI 的可用值和来源。有差异时并列原值。用户需要手工回查时，在报告列出题名、父条目 key、附件 key、已知 DOI、待核字段及理由，便于用户在 Zotero 中阅读、核对原始 PDF 或写作。

需补查 Crossref 的字段列入同一份用户清单。用户可按 DOI 查登记记录，缺 DOI 时按题名、作者及年份匹配，核对刊名和卷页后保留匹配 DOI。代理可核对用户提供的书目记录副本；尚无副本或匹配有歧义时将该字段标为未核实。书目记录用于确认引用，实验结论另附解析材料的证据位置。

## 报告与可复查的查询档案

沿用 `report/<YYYYMMDD>/报告标题.md`。在报告旁建立本次专用子目录，例如 `报告标题/queries/` 和 `报告标题/evidence/`。从首查到最终评估，主代理与各子代理遵循同一归档约定。可先分目录暂存，交付前将文件收齐到报告旁。

- **每一次查询**独立编号，包括扩词、零命中、失败和复查。清单写明子问题、执行者、时间、入口、完整查询串或命令、筛选条件、排序、模型和 `limit` / `top-k`（按实际使用填写）、返回条数、是否触及上限。先将完整 stdout 或工具/API 响应原样存档，再处理结果；失败时保留实际错误和状态，重试另起编号。
- **完整结果**按每次查询的返回顺序列出所有行，包括未采用项、重复项、筛除项。每行保留排名、题名、分数和原始 ID（可用时），标明采用情况。长表可作独立附件；报告的查询清单逐次链接结果表和原始响应，例如 `报告标题/queries/S1-01.md`、`报告标题/queries/S1-01.json`。零命中也链接原始响应。行数应与该次实际返回数一致，明确 top-k 覆盖边界。
- **采用的证据**随报告保存可独立阅读的解析文本摘录、所用解析图或表，以及所用书目核验记录。摘录保留解析文本原貌、上下文、解析文件名、父条目 key、附件 key、文档与分块 ID（如有）及页、节、行或图表位置。正文每个重要结论按编号链接精读证据与独立复核记录，并标出对应的查询编号、主代理采信理由及仍有的证据缺口。
- **交付前**从报告及各附件所在目录计算相对链接。逐个解析查询清单、全部结果、原始响应和采用证据的链接，核对目标文件能打开、引用位置正确。报告整体移走后应仍能读到这些材料；临时目录、聊天记录或本机绝对路径不能充当归档副本。
